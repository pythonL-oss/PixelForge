# PixelForge 算法引擎

**中文** | [English](README.en.md)

这是 [PixelForge](../README.md) 的算法部分，被我单独拎出来放在这个目录。
依赖只有 numpy 和 Pillow，装了 CuPy 的话重活会自动挪到显卡上；没有网络请求，没有模型权重，
就是一个纯计算的包，随手可以嵌到别的项目里。

它回答两个问题：

1. **这张图里的主体是哪儿？** —— 双色彩模型 + 显著性先验 + 多尺度马尔可夫随机场，
   难图会自己试六套策略并客观打分挑最优。
2. **怎么把它画成一张像样的 N×N 像素画？** —— 逐格候选色 + SSIM 结构坐标下降 +
   感知空间调色板。

---

## 目录里有什么

| 文件 | 内容 |
| --- | --- |
| `device.py` | 计算设备层。所有算子写成"类型保持"的：numpy 进 numpy 出，cupy 进 cupy 出，同一份代码两边跑 |
| `core.py` | 基础算子：OKLab、面积/双线性重采样、高斯/盒式/导向滤波、四类显著图、扫描线连通域、k-means |
| `segment.py` | 主体选择：双色彩模型、多尺度 MRF(ICM)、智能多方案搜索与打分、阴影剔除、三值图精修 |
| `pixelize.py` | 像素化：入格（居中/铺满）、逐格候选色、SSIM 结构优化、调色板与抖动、描边 |
| `demo.py` | 命令行示例，最简跑通 |
| `selftest.py` | 自检：和独立参考实现交叉验证（OKLab 往返 / 面积重采样 / 连通域 / 填洞 / 端到端） |

## 装上就能跑

```bash
pip install numpy Pillow        # 就这两个
pip install cupy-cuda12x        # 可选，装了自动用 GPU

python -m algorithms.selftest   # 自检，应该全过

python -m algorithms.demo input.png out -s 16,32,64 --colors 16 --preview 8
python -m algorithms.demo bricks.jpg out -s 16 --fill cover       # 方块材质：铺满不透明
```

在代码里用：

```python
from algorithms import core, PixelArtOptions, to_pixel_art

rgb, alpha = core.load_image("input.png")          # sRGB 0..1，float32
opt = PixelArtOptions(size=32, palette=16, fill="none", smart=True)
small_rgb, small_a, info = to_pixel_art(rgb, alpha, opt)
core.save_rgba("out.png", small_rgb, small_a)
print(info["palette_used"], info.get("seg_smart_choice"), info.get("seg_smart_score"))
```

只想用其中一段也行，两段是分开的：

```python
mask, seg_info = segment.segment(rgb, alpha, smart=True)     # 只找主体
g, ga, info = pixelize.pixelize(rgb, mask, pixelize.PixelOptions(
    out_w=32, out_h=32, fill="cover", palette=16))
```

## 数据是怎么流的

```
原图 ─► 缩略图(≤420px) ─┬─► 背景模型：边带 k-means
                        ├─► 前景模型：远离背景且不贴边的像素聚类
                        ├─► 显著图：谱残差 + 中心-周边 + 颜色稀有度 + 纹理能量
                        └─► 位置先验：居中程度、贴边程度
                                  │
                     数据项 + 先验 + 对比度自适应平滑 → 多尺度 MRF(ICM)
                                  │  ▲
                     用当前标注重估两个色彩模型（迭代几轮）
                                  │
                     ★ 智能模式：六套策略在 ≤320px 上试算 → 八项指标打分 → 选优
                                  │
                     阴影剔除 → 连通域打分选主体 → 三值图 + 导向滤波精修
                                  ▼
                           alpha (0..1)
                                  │
     主体包围盒等比入格（居中留白 / 等比铺满 / 拉伸铺满）
                                  │
     逐格统计：覆盖率 / α⁴ 纯净主体色 / 重要性加权均值 / 峰值细节色
                                  │
     SSIM 结构优化：逐格精确坐标下降（4×4 子像素、8×8 窗口）
                                  │
     细线判决 → 调色板 k-means → Potts ICM → 去噪 → 抖动 / 描边 / 色调
                                  ▼
                         N×N 像素画（RGBA）
```

## 算子细节

### 设备层

没有抽象成"后端接口"，而是让每个函数保持输入数组的类型：传 numpy 就得 numpy，传 cupy 就得 cupy。
启动时探测一次 CuPy + CUDA，能用的就用，不能用的静默回落，结果一致。也可以用环境变量
`PIXELFORGE_DEVICE=auto|cpu|gpu` 强制指定。这样写的好处是——上层代码完全感知不到 GPU 的存在。

### 色彩空间

sRGB 先转到线性光，再进 OKLab：

```
l = 0.4122214708r + 0.5363325363g + 0.0514459929b      (m、s 同理)
L = 0.2104542553·l^⅓ + 0.7936177850·m^⅓ − 0.0040720468·s^⅓
a = 1.9779984951·l^⅓ − 2.4285922050·m^⅓ + 0.4505937099·s^⅓
b = 0.0259040371·l^⅓ + 0.7827717662·m^⅓ − 0.8086757660·s^⅓
```

凡是涉及"距离""聚类""调色板"的地方都在 OKLab 里算。直接在 RGB 里算欧氏距离的话，
绿色那一大片的差异会被放大、蓝色和红色被压缩，聚出来的颜色会偏。

### 重采样

`resize_area` 是精确面积均值：用 cumsum 构造积分图，在分数边界处线性插值采样，
所以降采样时每个输出像素严格等于它覆盖区域的平均值（自检里和暴力实现对比，误差 1e-7 量级）。
升采样时它退化成双线性，够用；真要精确双线性有 `resize_bilinear`，半像素中心对齐。
`box_down2` 做整数倍盒式降采样，金字塔用。

### 滤波

`convolve1d` 是可分离一维卷积，边界用反射填充。`box_mean` 用积分图做到 O(1)/像素，
导向滤波和局部统计全靠它。

`guided_filter` 用的是 He 等人 2010 年的那一套，引导图取亮度：

```
a = cov(I,p) / (var(I) + ε)        b = mean(p) − a·mean(I)
q = mean(a)·I + mean(b)
```

它的作用是把抠图得到的软 alpha 收紧到真实轮廓上——边缘部分不再毛茸茸。

### 四类显著图

| 算子 | 怎么算 | 对什么敏感 |
| --- | --- | --- |
| `spectral_saliency` | 谱残差（Hou & Zhang 2007）：FFT 取 log 幅度，减去它自己的平滑版本，保留原相位反变换 | 与周围"不寻常"的区域 |
| `center_surround` | σ=2/4/8 三个尺度上和局部均值比颜色差 | 局部对比强的物体 |
| `color_rarity` | 颜色聚成 K 类，算每类到其它类的加权距离和，再映射回像素 | 荧光色、纯色金属、单色标志这类独一份的颜色 |
| `edge_density` / `texture_energy` | 梯度强度的局部密度 / 能量 | 细节多的物体 vs 平滑背景 |

四张图按权重拼成一张"显著性"，权重在 `segment._analyze()` 里，很好改。

### 连通域：行程扫描，不逐像素

逐像素 BFS 在 Python 里太慢了（一张 420×420 的掩膜要走十几万个点）。
这里的做法是：

1. 给掩膜左右各补一列 0，`np.diff` 一次求出所有行程（行内连续段）的起止列，纯向量化；
2. 相邻两行之间用 `searchsorted` 求重叠区间（8 连通允许对角相接，4 连通要求共边）；
3. 重叠的行程用并查集合并，路径减半 + 小索引优先。

复杂度是 O(行程数·α)，实际比逐像素快一个数量级。正确性在 `selftest.py` 里和 BFS 参考实现
对比过，8 连通和 4 连通都逐项一致。填洞就顺手了：对背景做一次连通域，没碰到画框的那些就是洞。

### 主体选择

**两个色彩模型。** 背景模型来自画框四周边带（默认 4% 厚度）的像素，在 OKLab 里做多起点 k-means
（k=5，取加权惯性最小的那组解）；阈值 `d_lo/d_hi` 取边带像素到最近中心的距离的 90 分位。
前景模型则是"离背景色远 + 不贴边"的像素再聚一次（k=4）。

数据项把"绝对距离"和"相对判断"混起来用：

```
s_abs = clip((d_bg − d_lo) / (d_hi − d_lo), 0, 1)          绝对：离背景色有多远
s_rel = d_bg / (d_bg + d_fg + ε)                           相对：更像背景还是更像前景
p_fg  = 0.62·s_abs + 0.38·s_rel

cost_bg(判为背景的代价) = p_fg + 0.35·λ_sal·sal
cost_fg(判为前景的代价) = (1 − p_fg) + center_bias·rad − λ_sal·sal
```

只有绝对项的话，渐变背景的中间色会被误判成前景；只有相对项的话，模型一旦被污染就全错。
混着用稳得多。

**能量与求解。** 8 邻域 MRF：

```
E = Σ_p cost(L_p) + λ·Σ_(p,q) w_t·exp(−‖I_p − I_q‖² / (2·mean‖ΔI‖²))·[L_p ≠ L_q]
```

平滑权重随颜色差指数衰减——颜色接近的邻居才"要求"同标签，跨过真实边缘时自动失效。
求解由粗到细：金字塔每层按棋盘格顺序做 ICM（同奇偶性的像素互不相邻，可以整批更新），
粗层结果上采样后作为细层初值。这比单尺度 ICM 稳，边界也更贴。

**难图多试几套。** 单套参数迟早会翻车：只要边带里同时存在两种差别很大的颜色
（背景本身就不统一），背景模型就会变成两个互不相干的东西，后面怎么调都救不回来。所以默认在 ≤320px 上试六套：

| 策略 | 改了什么 | 想抓住什么 |
| --- | --- | --- |
| 默认参数 | — | 通用情况 |
| 高显著 | λ_sal×2.2，阈值×0.9 | 视觉上突出的东西 |
| 稀有颜色 | λ_sal+0.45，阈值×1.15 | 画面里独一份的颜色 |
| 纹理边缘 | 细节能量 + 边界吸附生长 | 有细节的物体 |
| 居中主体 | center_bias+0.35 | 摆中间的东西 |
| 严格背景 | 阈值×1.35 | 背景干净、主体很淡 |

每套结果按八项指标打分（权重 0.04~0.19）：

```
s_bg      背景像素到背景模型的 70 分位距离越小越高   ——"背景能不能被解释"
s_fg      主体到背景模型的中位距离越大越高           ——"主体像不像主体"
s_edge    掩膜边界处的平均梯度 / 全图 95 分位          ——"边界是不是压在真实轮廓上"
s_sal     主体内显著度 − 背景显著度
s_tex     主体内纹理能量 − 背景纹理能量
s_comp    最大连通域占比 × 面积占比                   ——惩罚碎片
s_size    对 log2(cov/0.22) 的高斯型惩罚             ——面积别太离谱
s_center  主体重心离画面中心的距离
s_touch   掩膜贴画框的比例
```

胜出的那套会**回到工作分辨率重解一次**（低分辨率试算会留碎片，重解能抹掉），
再往下走阴影剔除和精修。某套得分 ≥ 0.78 直接结束，所以简单图片几乎不额外花时间。

**阴影。** 线性光下，投影阴影近似等于背景色乘一个系数。对每个背景中心做最小二乘投影求 k
和残差，`0.14 < k < 0.985` 且残差小者记为疑似阴影；再加两个门控：必须位于主体核心下方、
区域内部边缘密度低（阴影是平的）。两道门控是为了别把主体自己的暗部当成阴影删掉。

**精修。** 粗掩膜先分成"确定前景 / 未知窄带 / 确定背景"，窄带里的像素按颜色置信度判定，
最后用导向滤波把边界收紧（见上）。输出的 alpha 是软边，交给像素化阶段做覆盖率统计。

### 像素化

**入格。** 按主体包围盒等比缩放居中（`fill="none"`），或者等比放大到覆盖整张画布、
超出部分居中裁掉（`fill="cover"`，方块材质用），或者各向独立拉伸（`stretch`）。
采样统一在"工作画布"上做，超采样倍数 S=4，每个输出格子对应 4×4 个子像素。

**逐格候选色。** 每个格子算这几样：

- 覆盖率（子像素 alpha 均值）和峰值覆盖率；
- α⁴ 加权的"纯净主体色"——只有接近不透明的子像素才参与，抗锯齿边不会把颜色带偏；
- 重要性加权均值，重要性 = 0.62·梯度强度 + 0.55·局部色彩离群度（都归一化过）；
- 细节最强的那个子像素的颜色。

细线单独处理：覆盖率阈值吸附（≥50% 判主体）之后，再做一次"线状判决"——
沿某方向两端都在主体内、而垂直方向 1~2 格外全是背景，就把这一格捞回来。
1 像素宽的剑刃、天线就是靠这个活下来的，否则平均完就没了。

**SSIM 结构优化。** 这是整个引擎里最费劲、也最值钱的一段。

把 N×N 网格用半像素中心双线性放大到 2N 得到 U，2N 参考图 D 由画布面积降采样得到。
目标是让 U 和 D 在每个局部窗口上尽量像——也就是"放大后的像素画看上去要像原图"。

麻烦在于这是个非凸问题，逐格改颜色会互相影响。但有个性质可以利用：改动格子 (i,j) 只会影响
它的 4×4 个子像素（双线性的支撑集就那么点），进而只影响 8×8 个 5×5 窗口。
所以"把某一格换成候选色 c"这件事的收益可以**解析地精确算出来**，不需要近似：

```
4×4 受影响子像素（可分离双线性，q=[0.25,0.75,0.75,0.25]，r=[0.75,0.25,0.25,0.75]）：
U'[a,b] = q_a·q_b·c + q_a·r_b·nb_col[b] + r_a·q_b·nb_row[a] + r_a·r_b·diag[a,b]

局部 SSIM 贡献（只统计受影响的 8×8 个窗口，用覆盖率加权）：
S(c) = Σ_w cov_w·SSIM_w(U', D) / Σ_w cov_w

打分：score(c) = w_struct·S(c) − w_color·‖OKLab(c) − OKLab(c_ref)‖
```

候选色只有"均值族"（普通均值 / 重要性加权均值 / 纯净主体色），所以结构项可以把高光、内部边
拉出来，但不会凭空造出单像素噪点——这一点是踩过坑才改的，早期版本让候选包含亮暗极值，
结果光滑球面上出现"闪电状"假纹理。

实现上不是逐格 Python 循环（那样 128×128 要跑三十多秒），而是**整行一起算**：
一行的所有格子同时取 patch、同时算 SSIM，只对"有结构"的格子求值（平坦区域所有候选几乎一样，
算了也白算）。这样 64×64 从 1.18s 掉到 0.46s，128×128 从 4.80s 掉到 1.77s。

**调色板。** OKLab 里 k-means++ 播种、多起点取最优，然后合并感知上几乎一样的颜色
（不然渐变色阶会出现两条几乎相同的色带）。接着是 Potts 平滑 ICM 去孤立噪点——
强度不写死，而是取"最近调色板距离的中位数"当尺度，只用来打破近似平局。
早期版本用的是固定强度，结果把球面渐变压成了几个色块，教训。

**抖动与收尾。** 抖动有两种：有序 Bayer 4×4（加阈值偏移后取最近色）和 Floyd–Steinberg
误差扩散（误差在 OKLab 里扩散）。抖动和平滑互斥，开抖动就不跑 Potts。
描边分内部（原轮廓内一圈）和外部（向外扩一圈）。色调调整以主体亮度中位数为支点做温和拉伸，
这样整体明度不会被改跑偏（之前用 2%~98% 分位拉伸，白底主体直接被压暗，也是个坑）。

## 速度

12 核机器上的单线程实测：

| 场景 | 时间 |
| --- | --- |
| 800×800 的图 → 16/32/64 | 约 2~3 秒 |
| 3200×3200 的图 → 16/32/64 | 约 5~6 秒 |
| 8 张图 × 3 档，单进程 | 19 秒 |
| 同上，8 进程 | 5.4 秒 |

几个关键优化：

| 优化 | 收益 |
| --- | --- |
| SSIM 优化整行向量化 + 只算活跃格 | 64×64：1.18s → 0.46s；128×128：4.80s → 1.77s |
| 连通域换行程扫描 + 并查集 | 单图分割 3.6s → 1.3s |
| 结构清理（填洞 / 去小连通域）降到 256px 再做 | 同上 |
| 智能搜索在 ≤320px 试算 + 高分早停 | 简单图几乎不增加耗时 |

另外，多进程是在应用层做的（按文件切分），引擎本身是纯函数式的，想并行也容易。

## 自检

```bash
python -m algorithms.selftest

[1] OKLab 往返最大误差 1.1e-05
[2] resize_area 与暴力实现最大误差 1.4e-07
[3] 连通域 8/4 连通与 BFS 参考一致: 是
[4] 填洞: 通过
[5] 端到端 32x32: 形状 (32, 32, 3) ... 颜色 1
```

自检不依赖 PixelForge 应用层，把 `algorithms/` 单独拷出去也能跑。
